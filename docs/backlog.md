## 一期留下的小问题

| 问题 | 建议 |
|---|---|
| `coda.watch` 失败时静默，只剩手动刷新 | 作者定先不做，真实发生了再说 |
| 目录每取一页都重读并排序 | 看实测，卡了再加缓存 |
| 恢复时某页取失败，重试能取够条数，但滚动位置已用掉，回不到原处（二期评审 P2） | 很少发生，点几下能回去，先不修 |
| 恢复途中关闭页面，还没用上的已加载条数不会保存（二期评审） | 同上 |
| 启动超时只看首个 `root`；之后切会话如果等不到 `root`，不再有提示（二期评审） | 真实发生了再说 |
| 恢复上限约 2 万条，超过的回来后要再点「再显示」 | 已接受 |
| Mac 右键菜单有「在新窗口打开帧框」，点了没反应 | 客户端的问题，已提 #2140，插件不绕开（作者定） |
| 多个 2 万条目录同时按日期或大小排序时，快照超过总量上限（10 万条）会互相挤掉，轮流「再显示」每次都要重读（`0.4.0` 设计复审） | 很少发生，只是慢。真碰到再为多页加载预留容量 |
| 校验之后、打开之前，路径中间的目录被换成外链，或读目录（`readdir`）时目录被换，能读到工作目录外的内容或名字。读文件的最后一级已用 `O_NOFOLLOW` 挡住 | 作者定不修（PR #5 交叉评审报为 P1，作者看过复现后再次确认）。要从已验证的目录句柄逐级打开才能防，Node 没有这样的接口（实测 macOS 上 `/dev/fd/N/子路径` 打不开，`readdir` 不接受句柄），只能带原生模块或另起辅助进程。要在毫秒窗口里改工作目录才能踩中，能这么做的 Agent 本来就能读那些文件 |
| 一轮结束时已展开目录按日期或大小排序的都要重建快照，8 个 2 万条本机约 0.66 秒（`0.4.0` 设计复审） | 接受。大目录很多且明显变慢时，改成标记过期、按需重建 |
| 「添加到聊天」写草稿时，客户端有还没同步到服务端的输入，这些输入可能被服务端内容盖掉。这些改动只在客户端，插件看不到，修不了（`0.5.0` 设计，作者定接受） | 上游开放正式接口后换掉。真机确认写入后 Mac 和 iPhone 的输入框是否显示 |
| 文件夹大小统计占用视图并发上限的名额：同一时间最多 4 个，后来的列目录请求最多多等这几个任务；单个目录要整个读进来，几百万项的目录读目录本身会慢（`0.5.0` 设计） | 接受。统计有 20 万项、5 秒的上限，到了就给下限 |
| 「添加到聊天」写草稿超过 30 秒才回答：页面已经按超时处理，复制了文字并提示失败，之后草稿可能还是写进去了，用户再粘贴就会重复。不会自动重发（`0.6.0` 设计） | 很少发生，先不修 |
| 路径极长时（两级各 200 字符的目录），iPhone 横屏的行菜单约 600 点高，复制按钮在屏幕外（`0.4.0` 代码评审 P2） | 很少发生。`0.5.0` 行菜单会加项，到时给菜单加高度上限和内部滚动 |
| 菜单声明了菜单角色，但没有键盘焦点管理：打开后焦点不进菜单，方向键不能选，Escape 后焦点不回入口；VoiceOver 实际播报未验证（`0.4.0` 代码评审 P2） | 原有问题，排序项继承了它。鼠标和触屏不受影响，先不修 |
| 目录树和图标视图的选中没有读屏支持：键盘移动选中时没有 `aria-activedescendant`，VoiceOver 不会播报当前条目（`0.7.0` Mac 的打开方式，作者定不做） | 和上一条同类：焦点和读屏的整体设计，一起做。键盘和鼠标不受影响 |
| 按下和滑动时的触感（震动）：契约没有触感接口（`0.7.2`，作者定不做） | 等上游加桥再说 |
| harness 的 iPhone 菜单出现动画检查分两次页面求值（先点、再取动画），两次之间超过 150 毫秒时动画已播完，会误报失败（`0.7.2` 代码评审 P2，作者定先不修） | 3 轮未出现；真碰到就改成同一次求值里点并取动画，或用过渡测试的暂停机制 |

## 设计时要注意的约束

| 约束 | 来源 | 对本插件的影响 |
|---|---|---|
| iPad 分栏下，推入非会话页可能把列表选中清空，导致跳转失败 | #1344 | 作者决定不单独验证 iPad，风险记在这里 |
| 过期响应不能覆盖用户后来的选择 | #150 | 目录和文件读取都要丢弃迟到的回答 |
| 工作树可能存到自定义位置或外置盘 | #1002 | 只用 `checkout.path`，不假设路径规律 |
