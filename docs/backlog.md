| Markdown 预览：表格行内写 HTML 注释、表格后直接接注释块：单元格按 `|` 切分发生在去注释之前，注释里的 `|` 会被当成列分隔；很少见（`0.9.7` 代码评审，作者定不改） | 先不修；要修就让切分单元格时跳过注释 |
| Markdown 预览：图片替代文本里写 HTML 注释，注释原样进 `alt`；很少见（`0.9.7` 代码评审，作者定不改） | 先不修；要修就在取 `alt` 时去掉注释 |

## `0.9.x` 留下的问题

`0.9.5`～`0.9.7` 做完后整理的，都还没修，哪些做、哪一期做待定。「建议」一列是做法的方向，不是已定的决定。

### 打开方式与导航

| 问题 | 建议 |
|---|---|
| 「文本」类（代码、纯文本和所有认不出种类的文件）的打开方式切换是整类全局的：给一个 `.txt` 切一次，所有代码和未知类型的文件跟着变（`0.9.6`） | 要细分就把这一类拆开（如代码和纯文本分开），状态里记的类别跟着扩；先看有没有人真的碰到 |
| Markdown 的「预览 / 源码」选择不存：重载、重试、重新打开后回到「预览」；独立窗口保存的滚动位置是源码里的，重开后被恢复到预览上，位置对不上（`0.9.6`） | 要改就把模式连同滚动位置一起存、一起恢复 |
| Markdown 里的相对链接指向目录或不存在的文件时整页报错，而不是在原地提示；侧栏没有返回栈，点链接进了别的文件后只能回目录树再进；独立窗口每点一个相对链接就新开一个窗口（`0.9.6`） | 要改就先在点之前判断目标是不是文件，侧栏再加一层返回 |
| 在途期间再点同一个文件，在途的那次完成后会再打开一次（`0.9.5` 起的打开逻辑评审） | 要改就在合并意图时丢掉和在途相同的那个 |
| 已作废的取口令请求不会被取消：新文件要等旧请求返回或超时才轮到（`0.9.5` 起的打开逻辑评审） | 要改就让取口令也带取消 |
| `test/harness/markdown-layout.mjs` 找不到 Chrome 时会遗留进程和临时目录（`0.9.7` 打开逻辑评审） | 要改就在找不到 Chrome 的分支里也走清理 |
| 文档交给 Coda 打开后，口令随这个视图作废，之后 Coda 再取这个地址的资源可能 `404`（`0.9.5`） | 待作者真机验证，看 PDF、Office 文档打开后能不能一直读到；有问题再定口令的寿命 |

|---|---|

| 人为构造的约 1 MiB、多组不配对的反引号，渲染约 0.7 秒（`0.9.7` 代码评审） | 很少见；真有卡顿再缓存反引号配对的结果 |

### 本机流式服务

| 问题 | 建议 |
|---|---|
| `0.10.0` 已把 `xml`、`plist` 改按纯文本供应，所有回答都加了 `X-Content-Type-Options: nosniff`。`html`、`htm`、`xhtml` 仍按 `text/html`、`application/xhtml+xml` 供应（作者 2026-11-23 定，见三期设计第 27.5 节）：在 Coda 里打开不可信的 `html` 时，如果将来 Coda 在流式服务的地址下执行页面脚本，脚本可能带着同一个口令读到工作目录里的其他文件（`0.9.7` 实测 Coda 只显示源码，不执行） | Coda 支持 HTML 预览后，先用 `x1-probe.html` 复测；有问题就这几类改按纯文本供应，或把口令收窄到单个文件 |

### 清洗器

| 问题 | 建议 |
|---|---|
| 嵌套到 254 层以上时，折叠摘要会多出 1 层；深度到顶时 `pre` 的退路会折叠空白（`0.10.0` 代码评审） | 折叠摘要也算进深度预算；`pre` 的退路保留空白 |
